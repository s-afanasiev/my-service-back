# UI: модалка услуги

Документ для доработок. Если нужно добавить кастомную логику в верхней части окна (кнопки, баннер, другой виджет) — сначала прочитать этот файл, затем менять только указанные слоты, не ломая оболочку модалки.

Это **не** модалка карусели принтеров. У принтеров свой документ: `docs/ui-carousel-modal.md`.

---

## Зачем этот документ

Модалка услуги — отдельный оверлей на главной. Сверху фиксированная «герой»-зона (~400px), снизу название, цена и описание услуги.

Герой делится **вертикально на две половины**:

| Сторона | Слот | Сейчас | Куда класть новую логику |
|---------|------|--------|--------------------------|
| **Левая верхняя** | `[data-service-photo]` | фото или схема детали | кастом вместо/поверх фото: галерея, схема, превью |
| **Правая верхняя** | `[data-service-side]` | опциональные «кирпичики» брендов (у «картридж неоригинальный») | новый набор кнопок / другой виджет **этой** услуги |

Типичный следующий запрос: *«прочти `docs/ui-service-modal.md` и сделай кастомную логику в правой верхней части»* — это слот `[data-service-side]`. Фото слева не трогать, если не сказано иначе.

## Файлы

| Файл | Роль |
|------|------|
| `views/partials/services.ejs` | список услуг на главной + разметка модалки + весь клиентский JS |
| `views/partials/head.ejs` | CSS (классы `.service-modal…`, `.service-brand…`) |
| `views/partials/service-art.ejs` | SVG-схема детали, если нет фото |
| `server.js` | `SERVICE_DETAILS`, `mapService()`, колонки `services.description` / `image_filename` |
| `views/edit-service.ejs` | админка: название, цена, описание, фото |
| `assets/services/` | фото в git (имя из slug услуги) |
| `public/service-photos/` | загрузка через форму, в git не попадает |

Одна модалка на страницу. Контент подставляется при клике по строке услуги, окно не пересоздаётся.

## Оболочка (не ломать)

Поверх страницы, `z-index: 80`. Фон: `.service-modal-backdrop` (затемнение + blur).

**Размер диалога** (`.service-modal-dialog`): ~**70vw × 90vh** на десктопе; на узком экране почти весь вьюпорт (~96vw / 96dvh).

**Закрытие**

- крестик **слева сверху** (`.service-modal-close`, атрибут `data-service-close`);
- клик по затемнению (`data-service-close` на backdrop);
- Escape: если открыта карточка бренда в правом слоте — сначала назад к кирпичикам, иначе закрыть окно.

Клик **внутри** белого диалога окно не закрывает. Пока модалка открыта, на `body` висит класс `modal-open` (`overflow: hidden`; карусель принтеров не крутится сама).

Геометрия окна при смене услуги/бренда не прыгает: герой всегда 400px (на телефоне ~220px). Скролл длинных текстов — **внутри** своих блоков, не у всего диалога.

## Каркас DOM (сверху вниз)

```
.service-modal                    [data-service-modal]
  .service-modal-backdrop         [data-service-close]
  .service-modal-dialog
    .service-modal-close          [data-service-close]   крестик, left/top
    .service-modal-hero           [data-service-hero]    высота 400px
      .service-modal-photo        [data-service-photo]   ЛЕВАЯ верхняя (фото)
      .service-modal-side         [data-service-side]    ПРАВАЯ верхняя (кастом)
    .service-modal-head
      h3                          [data-service-title]
      .service-modal-price        [data-service-price]
    .service-modal-desc-block
      h4 Описание
      p.service-modal-desc        [data-service-desc]
```

Сетка героя: `grid-template-columns: 1fr 1fr` (фото слева, панель справа). Если правого слота нет, на героя вешается класс `is-photo-only` — одна колонка, фото на всю ширину, `[data-service-side]` скрыт (`hidden`).

Крестик абсолютно позиционирован слева сверху и лежит над фото. Правый слот крестик не перекрывает.

## Как открывается

Строка прайса: `.service-card` (`role="button"`, Enter/Space). Скрытые данные на карточке:

- `.service-art` — `<img>` или SVG;
- `.service-desc` — текст описания услуги;
- `script.service-panel` — JSON панели **правого** слота или `null`.

`openModal(card)`:

1. в `[data-service-photo]` клонирует картинку/схему;
2. заполняет title / price / desc;
3. `renderSide(panelOf(card))` — правый слот;
4. снимает `hidden` с модалки, фокус на диалог.

## Данные

Таблица `services`: `id`, `name`, `price`, `description`, `image_filename`.

Тексты и **панель правого слота** живут в `SERVICE_DETAILS` в `server.js`, ключ — нормализованное имя (`trim` + lower-case). `mapService()` при рендере главной подмешивает `panel` из этого объекта (в БД панель пока не пишется).

Описание услуги в БД заполняется один раз: `COALESCE(description, seed)` при старте. Дальше правится в админке.

Фото: загрузка в `public/service-photos/{id}.ext` **или** файл в `assets/services/` по slug имени (кириллица транслитерируется). Нет файла — SVG из `service-art.ejs` по `kind` (ролик, барабан, картридж…).

### Формат `panel` (правый слот)

```js
panel: {
  title: "Бренды",
  items: [
    {
      id: "hiblack",
      label: "Hi-Black",
      theme: "hiblack",                 // CSS-класс is-hiblack
      logo: "/assets/brands/hiblack.svg",
      description: "многострочный текст…",
    },
  ],
}
```

Нет `panel` или пустой `items` → правый слот выключен, фото на всю ширину героя.

Сейчас панель есть только у **«картридж неоригинальный»**. Кирпичики `inline` (`flex-wrap`): сначала в ряд, при нехватке места — следующая строка. Стиль каждого бренда свой (`theme` + логотип из `assets/brands/`):

## Текущая логика правого слота (бренды)

Состояния:

1. **Ряд кирпичиков** — `renderBrandList()`.
2. **Баннер выбранного бренда** — `renderBrandBanner(item)`: стрелка «назад», заголовок = `label`, логотип, текст с `overflow: auto`. Цвета баннера те же, что у кирпичика.

Клики делегируются на `[data-service-side]`: `data-brand-id` открывает баннер, `data-brand-back` возвращает список.

Это **пример** кастомной логики для одной услуги. Другая услуга может иметь другой `panel` или пустой правый слот.

## Левый верхний слот (фото)

Сейчас левая половина показывает клон `.service-art`. Кастом вместо фото (галерея, схема узла) — внутрь `[data-service-photo]`, высота героя 400px.

Картинки не обрезать: `object-fit: contain`, фон `#f8fafc`.

---

## Как добавить кастом в правый слот другой услуге

1. В `SERVICE_DETAILS` у нужного имени добавить `panel: { title, items }` с `theme` / `logo` при необходимости.
2. При другом UX — ветка в JS по `panel.type` или имени услуги; раскладка кирпичиков уже `inline` + wrap.
3. Описание пункта — в `items[].description`, не в `services.description` (то поле — текст **под** героем про саму услугу).
4. Логотипы класть в `assets/brands/` и отдавать как `/assets/brands/…`.
